# 燕山大学AI助手 - 数据框架设计

## 一、数据存储架构

### 双层存储设计
| 存储类型 | 数据库 | 用途 |
|---------|--------|------|
| 结构化数据 | MySQL | 用户信息、知识元数据、配置、日志 |
| 向量数据 | Milvus | 文本嵌入向量，用于RAG检索 |
| 文件存储 | 本地文件系统/OSS | PDF、文档、图片等原始文件 |

## 二、数据分类（对应知识库目录）

### 1. 基础校园数据（高优先级）
| 分类 | 数据内容 | 获取方式 | 更新频率 |
|------|---------|---------|---------|
| 校史校情 | 学校简介、历史、校训 | 官网爬虫 + 手动整理 | 低 |
| 规章制度 | 学生手册、管理规定 | PDF文档解析 | 低 |
| 院系专业 | 学院介绍、专业设置 | 官网爬虫 | 中 |
| 校园地图 | 建筑信息、地点别名 | 手动整理 + 用户贡献 | 中 |
| 教学资源 | 课程信息、培养方案 | 教务系统对接 | 中 |

### 2. 学习资源（中优先级）
| 分类 | 数据内容 | 获取方式 |
|------|---------|---------|
| 电子书 | PDF教材、参考书 | 用户上传 + 协会资源 |
| 网课推荐 | 课程链接、评价 | 用户贡献 |
| 竞赛库 | 竞赛信息、往届题 | 手动整理 + 爬虫 |
| 考研保研 | 经验分享、资料 | 用户贡献 |

### 3. 生活服务（中优先级）
| 分类 | 数据内容 | 获取方式 |
|------|---------|---------|
| 食堂信息 | 菜单、窗口 | 手动拍照 + OCR |
| 周边小吃 | 店铺信息、推荐 | 用户贡献 |
| 宿舍信息 | 楼栋、设施 | 手动整理 |

### 4. 互动内容（低优先级，用户生成）
- Q&A问答、学长留言、经验分享、社团信息

## 三、数据获取渠道（可落地）

### 渠道1：官方网站爬虫（被动获取）
**目标网站：**
- 燕山大学官网 (ysu.edu.cn)
- 各学院官网
- 教务处网站

**技术方案：**
- 使用 BeautifulSoup + requests
- 遵守 robots.txt，设置请求延迟
- 增量更新，避免重复爬取

### 渠道2：文档解析（手动导入）
**支持格式：** PDF、Word、Markdown、TXT

**处理流程：**
1. 用户上传文件到 `/uploads`
2. 使用 MinerU / PyPDF2 解析文本
3. 文本分块 → 向量化 → 存入 Milvus
4. 元数据存入 MySQL

### 渠道3：用户贡献平台（UGC）
**功能设计：**
- 简单的Web表单提交
- 内容审核机制（先审后发）
- 积分/贡献值激励

### 渠道4：手动录入（Excel/CSV批量导入）
**适用场景：**
- 结构化数据（竞赛信息、建筑列表等）
- 初期数据快速导入

## 四、数据处理流水线

```
原始数据 → 清洗 → 分块 → 向量化 → 索引 → 可用
         ↓
      元数据存入MySQL
```

## 五、MySQL 数据表设计

### 核心表
- `knowledge_documents` - 知识文档主表
- `knowledge_chunks` - 文本分块表
- `data_sources` - 数据源管理
- `crawl_tasks` - 爬虫任务表
- `user_contributions` - 用户贡献表

## 六、实施优先级

### Phase 1（MVP）
1. 搭建基础数据表结构
2. 实现文件上传解析流程（PDF/Markdown）
3. 实现简单的手动录入功能
4. 导入第一批核心数据（校史、规章制度）

### Phase 2
1. 开发官网爬虫
2. 用户贡献平台
3. 数据审核流程

### Phase 3
1. 教务系统对接（需要学校配合）
2. 高级数据管理后台
